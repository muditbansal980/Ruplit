# GSAP motion for the language-selection page (`/select-language`)

Goal: add calm, trust-building motion to the existing page without touching its state logic (`useLanguage` store, i18n detection, confirm→`/greeting` flow all stay as-is).

## Files to change

### 1. `src/app/select-language/page.tsx`
- **Entrance:** a `gsap.context` timeline in `useEffect` scoped to `<main>`: header fades in first, then `.lang-card` elements stagger in one at a time (`y:16 → 0, opacity 0 → 1`, duration 0.4, stagger 0.09, ease `power2.out`), then the OK button. Uses `.from()` so elements are visible by default (no-JS / reduced-motion safe).
- **Warmth element:** a small inline "saathi face" SVG (leaf-green circle, white eyes + smile) above the heading — gently bobs (±3px, sine.inOut yoyo) and blinks every few seconds. Chosen instead of Spline/3D for zero load risk on low-end devices.
- **Selection → transition (`handleConfirm`):** GSAP timeline replacing the bare `setTimeout`:
  1. selected card pops (`scale 1.03 → 1`, 150–180ms each step),
  2. deliberate ~250ms pause (visible proof the tap registered before anything changes),
  3. whole screen crossfades out with a slight upward slide (`opacity 0, y:-16`, 350ms, `power2.out`), then `router.push("/greeting")` in the timeline's `onComplete`. Total ≈1s; the confirmation banner still appears immediately via `setConfirmed(true)` (with its own 300ms fade-up) and keeps its `aria-live` semantics.
- Reduced-motion path: instant confirm → short 400ms delay → push, no animation.

### 2. `src/components/ui/LanguageCard.tsx` (already drafted, blocked by plan mode)
- Add `data-lang-code` attribute + `lang-card` class (hooks for the page's timelines).
- **Selection feedback:** on `isSelected` becoming true, a 150ms scale-up + 200ms settle pop; pairs with the persistent state change (existing border/background swap) plus a new green **checkmark** icon next to the name so state is never conveyed by motion alone.
- Fix: `transition` → `transition-colors` so the CSS transition only covers colors and doesn't fight GSAP's transform.

### 3. `src/components/ui/SpeakButton.tsx` (already applied before plan mode activated — will be kept/verified)
- Continuous "breathing" pulse on the button: `scale 1 → 1.05`, 0.75s each way, `sine.inOut`, yoyo, repeat -1. This is intentionally the most noticeable motion on the page.

## Constraints honored
- Easings only `power1/power2/sine` — no elastic/bounce.
- Every animation ≤400ms except the two ambient loops (speaker pulse, saathi face).
- All GSAP work guarded by `matchMedia("(prefers-reduced-motion: reduce)")` with static fallbacks; tweens killed in effect cleanups.
- Console logging in existing components preserved.
- Verify with `next build`, then visually confirm entrance, tap feedback, and the handoff transition in the browser at mobile + desktop sizes.
